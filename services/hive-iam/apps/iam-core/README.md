# Hive IAM Core API

Central IAM Core API for the Hive control plane. It provides authentication,
authorization, OAuth2/OIDC flows, MFA/WebAuthn support, service accounts,
sessions, groups, device trust, password policy, system-user inspection, and
audit ingestion.

## Features

- RS256 access tokens and rotating refresh tokens
- Argon2id password hashing
- RBAC with users, roles, groups, and service accounts
- OAuth2 Authorization Code + PKCE and Client Credentials flows
- OIDC discovery and ID token support
- WebAuthn/FIDO2 credential registration and login
- Password policies and breach-check helpers
- Session and device trust/risk APIs
- Agent audit ingest through `x-agent-token`
- Append-only audit log files and database-backed audit queries

```bash

bash scripts/generate-keys.sh
npm run db:generate

```

Production-style local run:

```bash
npm run build
```

## Environment

See `.env.example`.

| Variable | Purpose |
| --- | --- |
| `PORT` / `HOST` | Listener configuration |
| `DATABASE_URL` | SQLite database path |
| `REDIS_URL` | Redis connection for queues/rate limits |
| `JWT_PRIVATE_KEY_PATH` / `JWT_PUBLIC_KEY_PATH` | Active RS256 signing keypair |
| `JWT_PREVIOUS_PUBLIC_KEY_PATHS` | Comma-separated retired public keys retained through the token-expiry overlap |
| `JWT_ISSUER` | Expected issuer for tokens |
| `COOKIE_SECRET` | Dashboard/session cookie secret |
| `TLS_CERT_PATH` / `TLS_KEY_PATH` | HTTPS certificate paths |
| `CORS_ORIGIN` | Allowed dashboard origin |
| `IAM_AGENT_SECRET` | Shared secret for agent audit ingest |
| `SEED_HIVE_CLIENT_SECRET` / `SEED_HIVE_ROUTER_CLIENT_SECRET` | Required protected inputs on first confidential-client creation; ignored for existing hashes during routine seed |
| `SEED_ADMIN_PASSWORD` | Initial administrator password (at least 16 characters) |
| `SEED_HIVE_PUBLIC_URL` / `SEED_HIVE_ROUTER_REDIRECT_URI` | Public Hive URL and Router OIDC callback used for the built-in client redirect URIs |
| `SEED_SECURITY_EXPORTER_CLIENT_SECRET` | Optional; creates the read-only `security-exporter` client-credentials client |
| `SEED_EXAMPLE_PORTAL_CLIENT_SECRET` / `SEED_EXAMPLE_PORTAL_REDIRECT_URI` | Optional; creates the `example-portal` example OIDC client |
| `IAM_MACHINE_CLIENT_POLICIES` | Optional JSON map of additional machine-client audience/permission/lifetime policies |

## Deploy

From the workspace root:

```bash
bash scripts/deploy-iam-core.sh
```

In the consolidated Hive deploy, use the root `npm run deploy` whenever possible
so Memory, IAM, and Router are updated in order. IAM deploys preserve existing
secrets and bootstrap `SEED_HIVE_ROUTER_CLIENT_SECRET` only on first install.
An existing host with no recoverable Router secret fails deployment instead of
silently replacing the credential hash.

The seed never invents a confidential-client credential and never rotates an
existing Argon2 hash. First-install values (supplied or generated by the deploy) remain in the
root-protected `/opt/hive-iam/.env`, where Router can recover its credential.
Rotate an existing client only with authenticated
`POST /api/v1/clients/:id/rotate-secret`; this produces a `client.secret_rotated`
audit event and requires a replacement secret of at least 32 characters.
